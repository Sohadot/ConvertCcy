Currency Passage Ontology

Eight classes organize every jurisdiction's response to currency movement. This is the conceptual foundation that makes ConvertCCY the category's vocabulary maker, not follower.

The Eight Classes

Currency Movement Governed

When value crosses a border, jurisdictions apply rules. These eight classes capture every dimension of that governance:

1
Declaration Regimes
Thresholds, currencies of denomination, and who declares. The primary regulatory trigger for cash movement.
Read class →
2
Exchange Controls
Access restrictions, approval regimes, and license requirements. How governments gate the conversion itself.
Read class →
3
Residency Divergence
Resident vs non-resident treatment asymmetry. Many jurisdictions apply different rules by traveler type.
Read class →
4
Import/Export Ceilings
Cash in vs cash out asymmetry. Restrictions that differ based on flow direction.
Read class →
5
Reporting Obligations
Who reports (individuals, banks, carriers) and to whom. The compliance layer beyond declaration.
Read class →
6
Channel Restrictions
Different rules for cash, transfer, card, and informal channels. How the mechanism of movement matters.
Read class →
7
Penalty Regimes
Consequences for violation: confiscation, fines, criminal exposure. The enforcement teeth behind the rules.
Read class →
8
Rate Regimes
Floating, pegged, dual-rate, and parallel-market economies. How exchange mechanism shapes access.
Read class →
Category Language

These eight classes are ConvertCCY's proprietary language system. They are not general frameworks imported from economics textbooks. They are the organization that makes reference-grade FX rules data coherent and citable. Every country rules page encodes these classes. Every ontology page links to jurisdictions embodying that class. Together they are the asset's competitive language layer.

Framework

How Ontology Connects to Rules

The ontology is not independent reference material. It is a mirror of the schema:

  • Each country rules JSON entry has fields matching these eight classes.
  • Every ontology page lists which jurisdictions currently hold published or verified data in that class.
  • Rules pages link backward to ontology class pages, making each entry part of a larger governance landscape.
  • The Passage Check engine (P3) will use ontology class linkage to help readers navigate consequences: "your scenario crosses into Exchange Controls and Reporting Obligations".
Authority Position

By publishing the ontology openly, ConvertCCY stakes a claim: "This is how currency governance organizes." Other reference systems can adopt it, debate it, and improve it. The ontology is the asset's language moat.
