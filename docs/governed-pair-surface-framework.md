Public governance document. It describes what the repository implements today. Where something
is planned or proposed, it is marked as such and is not described as current functionality.

* **Reconciled against:** `main` at `ed6a4f67bd4ce1322e3fee24166c4411d82b1990`, the merge of PR #136 (SEO-A4.5).
* **Supersedes:** the earlier working draft titled "8,340 Page Governing Framework". That draft
  was never committed. This file is the single authoritative version.
* **Companion documents:** `docs/instrument-classification-policy.md` (A4.1),
  `docs/precious-metals-methodology.md` (A4.4) and `docs/institutional-units-methodology.md` (A4.5).

## 1. Purpose and doctrine

This document governs the **pair surface**, which is the set of directed currency-pair pages under
`pages/`. It records how that surface was brought from a largely unindexed state to a governed,
semantically correct and measurable state.

The programme follows one sequence. Each step depends on the one before it:

```
Crawlability → Static Value → Instrument Classification → Correct Semantics
            → Evidence / Provenance → Indexability → Measurement
```

Two governing principles apply to every layer:

> **Missing rate does not mean invalid page.**
>
> **Available provider rate does not mean correct semantic meaning.**

The four parties involved have separate roles:

> The repository defines intended state.
> Deployment exposes intended state.
> Google independently evaluates it.
> Google Search Console (GSC) measures Google's response.

Repository validators prove that the intended state is implemented correctly. They cannot prove
that Google indexes it. Measurement is covered in §10.

## 2. What "8,340" means

8,340 was a **GSC point-in-time total** of non-indexed URLs. It is **not** a deterministic
pair-page cohort, and the repository cannot reproduce it.

| GSC status | Count |
|---|---|
| Crawled — currently not indexed | 7,173 |
| Page with redirect | 1,165 |
| Redirect error | 1 |
| Not found (404) | 1 |
| **Total** | **8,340** |

* **The 1,165 redirects are not defects.** They are intentional permanent redirects:
  * 999 exact 301 rules in the repository's `_redirects`, which map legacy root pair URLs
    (`/xxx-to-yyy`) to canonical `/pages/xxx-to-yyy.html` and are generated by
    `scripts/build_redirects.py`;
  * the remainder are HTTP → HTTPS and `www` → apex redirects applied at the host.

  Redirect URLs count toward GSC's non-indexed total, but they are not failed pair pages. They
  are never expected to be indexed.
* **No complete GSC URL export was ever obtained** for the 8,340 records. That population
  therefore cannot be reconstructed from the repository, and no layer is defined in terms of it.
* The **repository-defined semantic cohorts** in §4 are the deterministic implementation surface.
  GSC is the measurement layer.

## 3. Indexation-recovery sequence

| Step | Layer | Role in recovery | Status |
|---|---|---|---|
| 1 | **A2: crawlability** | Every pair page is reachable through ordinary links | Implemented |
| 2 | **A3: static value** | Pair-specific state is visible in the generated HTML | Implemented |
| 3 | **A4.1–A4.5: semantic correction** | Each instrument is rendered as what it is | Implemented (A4.5 merged in PR #136) |
| 4 | **A4.6: source coverage** | Residual unsupported cohort | Planned. The scope decision is pending (§7). |
| 5 | **GSC measurement** | Cohort-level indexation measurement | Proposed as a future measurement sprint (§10) |

A2 and A3 are the **primary** indexation-recovery interventions. The A4 work corrects meaning on
top of them and does not replace them.

The jurisdictional-intelligence layers form a separate enrichment dimension (§12). These are
CRIS, the Rules Dataset, Passage Check, the ontology, the Passage Brief and the Agent Interface.
They were **not** the primary cause of the original indexation problem.

### 3.1 A2: internal link graph (Implemented)

**Audit finding:** before A2, approximately **90.7%** of pair pages were orphaned or insufficiently
connected, meaning they were reachable in practice only through the sitemap.

**What A2 does:** A2 repaired the link graph across the full pair surface. It added one
deterministic hub per currency at `currencies/<code>.html` (170 in total), a `currencies.html`
index, and a bounded, deterministic related-pair graph that has no reverse-only 2-cycles.

**Crawl path:**

```
Homepage (index.html) → currencies.html → Currency Hub → Pair Page
```

This puts every pair page **three clicks** from the homepage. The gate asserts a maximum pair
depth of 3, that every pair is reachable, that no pair is reachable only from the sitemap, and
that every hub links all of its FROM and TO pairs.

### 3.2 A3: static value (Implemented)

A3 is the static-value and crawl-visible data layer for **all 28,730** pair pages. It puts
pair-specific state into the generated HTML instead of relying only on runtime JavaScript:

* a dated reference value derived from `data/rate_snapshot.json`;
* a static conversion table;
* explicit unsupported states;
* FAQ and FAQPage JSON-LD that tell the truth about whether a value exists (A3.1).

Runtime JavaScript (`assets/js/pair-rate.js`) only enhances what is already in the HTML. Marked
regions (`STATIC-RATE`, `STATIC-RATE-TABLE` and `RATE-SCRIPT`) keep later rewrites targeted and
verifiable.

### 4.1 The central lesson: provider values are not semantic evidence

A4 does not exist only because 4,238 pages had no rate. **A4.2–A4.5 rewrote 5,778 pages, and
2,142 of them already carried a provider-supplied FX value.** That value was not enough evidence
that those pages should remain ordinary converters:

* **Historical instruments.** Withdrawn or superseded codes such as BGN, HRK, ZWL and ANG still
  received provider values. Showing those values as live rates would misstate the instrument.
* **Institutional units.** XDR (an IMF reserve asset defined by a basket) and CLF (an indexed unit
  of account) were rendered as ordinary FX. Their governing value is the one the issuer
  publishes, not a market quote. For CLF, the provider-implied value differs from the official UF
  by more than the provider's precision explains (`docs/institutional-units-methodology.md` §11).

The router therefore asks **instrument policy first**. Snapshot coverage only distinguishes
`ordinary_fx` from `unsupported_specialized` after every policy branch has declined the pair.

## 5. Semantic router (as implemented)

The router is `generate.pair_semantic_treatment(from_code, to_code, snapshot)`, and it is the
single decision point. Its precedence on `main` is:

```
standards_special      instrument_policy.resolve_pair(...).converter_behavior == "none"
  → historical          converter_behavior == "archival_only"
  → precious_metal      either side is_precious_metal (XAU, XAG, XPT, XPD)
  → institutional_unit  either side is_institutional_unit (XDR, CLF, UYW, XUA, XSU)
  → ordinary_fx         static_pair_rate(...) is not None
  → unsupported_specialized   otherwise
```

* `pair_rate_treatment` derives its result from the router through `_RATE_TREATMENT`.
* `SPECIAL_TREATMENTS = ("historical", "standards_special", "precious_metal", "institutional_unit")`.
* Precedence examples:
  * XAU/XTS is a standards page.
  * XAU/BGN is a historical page.
  * XDR/XTS is a standards page.
  * XAU/XDR is a metal page with an institutional-side note.

> **A dedicated A4.6 live-fiat coverage treatment is planned but is not part of the implemented
> semantic router.** No `restricted_fiat`, official-versus-market or regime-aware branch exists
> today.

### 6.1 Layer notes

* **A4.2 (historical, 2,296 pages).** Pages carry no LIVE or SNAPSHOT state and no rate runtime.
  They show only verified, labelled figures: historical fixed conversion, redenomination or fixed
  legal parity. Provider-alias leaks are blocked, and FAQ and JSON-LD stay aligned.
* **A4.3 (standards, 674 pages).** **All 674** XTS/XXX pair pages are `noindex,follow` and
  self-canonical, and **all 674** are excluded from `sitemap.xml`. This is a complete cohort
  policy, not a partial one. The XTS and XXX hubs remain indexable and cite the registry.
* **A4.4 (metals, 1,268 pages, 4 hubs).** No metal price is published, because no source with
  publication rights is available. Licence states are `not_usable` or `license_unclear`. Unit
  wording keeps three evidence roles separate:
  * **ISO 4217 → code identity.** ISO defines XAU, XAG, XPT and XPD but **does not state a
    measurement unit**.
  * **Market convention → troy-ounce quotation context.** The troy ounce is the customary market
    convention used by the ConvertCCY metals reference architecture.
  * **NIST → conversion-factor evidence.** The troy-ounce-to-gram factor (rounded) is cited from
    NIST SP 811.
* **A4.5 (institutional, 1,540 pages, 5 hubs: XDR, CLF, UYW, XUA, XSU).**
  * It has its own institutional snapshot and value model (`institutional_reference.py`), with
    issuer-cadence freshness, licensing and methodology evidence.
  * **No unlicensed numeric institutional value is published.** The current state is
    `activation_state: reference_layer_only`, and every source is `license_unclear`.
  * Generation is targeted (`--institutional-units-only`) and the cohort comes from policy. The
    sprint verified a semantic freeze outside the cohort and an idempotent second run (0 files
    changed).

## 8. Governance vocabulary → repository fields

This document introduces no second status system. Each governance term corresponds to an
existing field:

| Governance meaning | Repository field and state | Where |
|---|---|---|
| Verified claim or figure | `verification_status: verified` | `documented_conversion` entries in `data/instrument_classification.json` (6 entries are `verified`) |
| Source verification pending | `verification_status: requires_source_verification` | the same enum. The `fact_policy` in `meta` forbids publishing such facts. |
| Classification certainty | `classification_confidence`: `high` / `medium` / `low` | per instrument. Current counts: 161 high, 8 medium, 1 low. |
| Source reuse and licensing | `license_state`, which is publishable only as `redistribution_permitted` or `attribution_required` | metal and institutional snapshots |
| Public numeric activation | `activation_state`: `reference_layer_only` / `source_activated` | `data/metal_reference_snapshot.json`, `data/institutional_reference_snapshot.json`, `precious_metals_reference.pricing` |
| No usable value | `value_type: unavailable` | returned by `metal_reference.value_view` and `institutional_reference.value_view`; never stored |
| Unresolved classification or source issue | `review_flags`, plus layer-specific states | per instrument |
| Example of a layer-specific state | `activity_status: status_unresolved` (XSU) | `institutional_units_reference.units.XSU` |

> **verification ≠ confidence ≠ licence ≠ activation ≠ availability.**
> These are separate governance axes. A fact can be verified while its source licence is unclear.
> A methodology can be verified while activation is `reference_layer_only`. A classification can
> be high-confidence while no value is available.

## 9. Success criteria

Success is measured on three separate axes.

**Technical success.** This axis is proven by the repository.
* The cohort is deterministic and derived from policy, not from hard-coded lists.
* No file outside the target cohort changes, and a second targeted run produces zero diff.
* All validators and tests are green in the Governance Gate.
* Robots, canonicals and sitemap membership are correct per class.
* Structured data matches visible content. Special pages carry no WebApplication.

**Semantic success.** This axis is proven by the repository.
* The generic `unsupported_specialized` bucket shrinks. Over the programme it went from 4,238
  pages to 602.
* Every instrument has the correct role, and no page implies a provider rate means something it
  does not.
* Provenance is explicit, and unresolved states (licence, activity, verification) are declared
  rather than hidden.

**Search and indexation success.** This axis is measured externally, in GSC.
* "Crawled — currently not indexed" falls for the surfaces **intended** for indexation.
* Cohort-level indexation improves once the sitemap segmentation in §10 exists.
* Deliberately `noindex` standards surfaces are never indexed.
* Intentional redirects are **not** expected to become indexed.

> **"8,340 → 0" is not a valid success metric.** That total includes intentional redirects and
> deliberate `noindex` pages, and its URL population was never exported.

## 10. Measurement and indexation success

Validators prove that the implementation is correct. **They do not prove that Google indexes the
pages.**

**Current baseline (implemented).** Today the programme is measured with GSC Page Indexing
totals, plus sample or exported URLs where they are available. The sitemap is a single file,
`sitemap.xml`, with **28,308** URLs: 28,056 pair pages, which is 28,730 minus the 674 noindex
standards pages, plus 252 other URLs.

**Future semantic measurement (proposed as a separate sprint, not implemented).** Restructure
sitemap output into a **sitemap index** with semantically separated child sitemaps, for example:

* ordinary FX;
* historical;
* precious metals;
* institutional units;
* currency hubs;
* any other meaningful indexable class, such as articles and rules.

The GSC Page Indexing report can be filtered by submitted sitemap. This split would give
**cohort-level indexation numbers** without needing the original 8,340-URL export.

This is deliberately **not** done here. A change to the sitemap structure deserves its own sprint
with scoped tests, semantic-freeze controls, and a resolution of the `lastmod` debt (§11 B) so
that child sitemaps do not churn.

## 13. Working rules for pair-surface sprints

These rules applied to every sprint from A2 to A4.5 and remain in force:

1. Before starting, verify the baseline SHA against `origin/main`. Stop on any mismatch.
2. Work on a dedicated branch and open a PR. Never merge automatically.
3. Derive the cohort from policy. Generation is targeted and idempotent: a second run produces
   0 changes.
4. Run a semantic-freeze proof: zero changed files outside the target cohort and its hubs.
5. Do not change robots, canonicals or the sitemap unless the layer's policy requires it. Any
   sitemap change is merged additively.
6. Do not touch jurisdiction rules, Switzerland files, claims, bindings or evidence packs.
7. Never publish a value without a licence, provenance and a timestamp. Never fabricate a quote.
8. Keep the repository public-safe: no credentials, tokens, private infrastructure or private
   commercial terms.
