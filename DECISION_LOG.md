## Phase 1 — Initial Security Hardening
**Status:** Merged to main

- Added `.gitignore` (Python cache, venv, OS/editor artifacts)
- Hardened HTTP security headers in `_headers` (source-of-truth documentation only — not processed by GitHub Pages)
- Live headers applied via Cloudflare Transform Rules → Modify Response Headers
- Scope: `convertccy.com` and `www.convertccy.com` only — does not auto-apply to future subdomains
- HSTS: `max-age=31536000` without `includeSubDomains` pending subdomain audit
- CSP: `unsafe-inline` retained for GTM compatibility; explicit domain whitelist for GTM, GA, Formspree, region1.google-analytics.com

## Phase 3 — Generator Guard + Authority Layer
**Status:** Complete, on main

### Decision: methodology.html, manifesto.html, framework.html are now manually managed

These three pages were previously auto-generated by `generate.py` on every build run.

They are now **manually managed authority pages**. The generator will skip them if the files exist.

#### What changed in generate.py

Added `MANUALLY_MANAGED_BUILDERS` constant and rewrote `generate_support_pages()`:

- `currencies.html` and `disclaimer.html` continue to regenerate on every run
- `methodology.html`, `manifesto.html`, `framework.html` are skipped if already present
- On first-ever build of a fresh repo clone, they are generated once, then become manually owned

#### Rule from this point forward

Any future edit to these three pages must go through:

```
branch → PR review → merge
```

Not direct-to-main.

#### Smoke test confirmation

Running `generate.py` after this change produces:

```
Skipped methodology.html — manually managed, file exists
Skipped manifesto.html   — manually managed, file exists
Skipped framework.html   — manually managed, file exists
```

## Standing rules (all phases)

- One concern = one PR = one branch
- No push to main directly
- No auto-merge
- No noindex on pair pages
- No SEO-impacting changes hidden inside security PRs
- Manual workflow preferred over API-dependent automation
